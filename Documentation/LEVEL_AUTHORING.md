# Reproducing and validating the campaign

Run from the SortScape project root:

```sh
swift run -c release CampaignTool generate
swift run -c release CampaignTool validate Sources/PuzzleCore/Resources/campaign.json Documentation/level-validation.json
swift test
xcodegen generate
```

The first command generates a deterministic candidate pool, rejects duplicates, solved starts, unsolvable states, and search-budget failures, selects 100 smoothly ordered boards, independently validates them, and only then atomically writes the campaign and report. Do not edit the archived beginner.json: recipe version 0 and save migration rely on its immutable 15 layouts. Recipe version 1 specifies SplitMix64 + Fisher–Yates over four copies of each color, split into full tubes plus empty tubes. It is independent of Swift's random-number implementation and hash iteration order. All seeds and generation parameters live in each level's JSON recipe. The pool schedule/selection algorithm is versioned in CampaignTool source; schemaVersion 2 uses generatorVersion 1.

`campaign.schema.json` defines the structural schema. The Swift loader enforces the same types/keys and adds consecutive unique IDs, tier boundaries, four pieces per color, at least one empty tube, capacity four, non-solved starts, seed reproduction, and duplicate rejection. Board identity ignores container order AND color permutations. No visual reskin is counted as a new board. The validator independently solves every board and replays each solution through PuzzleState.

A* uses a binary heap, tube-permutation state reduction, and an admissible longest-bottom-run bound. Search effort is the number of expanded states, not wall-clock time, so metrics reproduce across machines. Search budget exhaustion is distinct from an unsolvable result. Small-board optimality is checked against an independent breadth-first search in tests. Candidates are bounded at 30,000 expanded states; validation and the app's solver use their documented budgets.

Difficulty is an estimate, not a human playtest rating:

- complexity = 2 × adjacent color boundaries + 4 × number of colors + 6 for a single empty tube
- score = 3 × solution length + complexity + floor(log2(expanded states + 1))
- sort by measured score, then version/seed for stable ties
- preserve First Light and Tidal Pools as the first two tutorials; sample the remaining verified distribution in ascending score order
- reject a campaign with a decreasing score or adjacent increase over 12; the bundled campaign's largest increase is 5

Tiers are Beginner 1–20, Easy 21–40, Medium 41–65, Hard 66–85, Expert 86–100. All tiers use the original one-piece sorting rules and existing four-color symbol palette, with strategy guidance on the selection screen. No unexplained mechanics are introduced.

Stars: a completed board always earns at least 1. Earn 3 at solution length + max(1, length/5) moves or fewer; earn 2 at length + max(3, length/2) or fewer. Stars and best counts can only improve, and a replay never grants a second first-completion reward. Hints remain free and do not lower stars. The solution benchmark is generated by the versioned solver; keep catalog metrics stable in a published campaign.

Changing published level identity requires an explicit migration. v1 saves migrate by canonical board identity, preserving mapped scores/stars, old unlocked range, and all earned coins. Unselected historical scores are retained in legacyBestMoves and their rewards in legacyCoins. The original save is backed up before the first v2 write. Never attach an old score to a different board or silently replace corrupt saves.
